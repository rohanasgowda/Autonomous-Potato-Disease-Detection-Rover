# Demonstration Guide

This guide outlines a short demo workflow that exercises the full pipeline (capture → inference → treatment → backend → notification).

Preparation checklist
- Backend running: `cd backend && uvicorn app.main:app --reload --host 0.0.0.0 --port 8000`.
- Place `model.tflite` and `labels.json` under `phase4/runs/mobilenetv3/` on the host or Pi.
- Configure OpenRouter API key in `phase3/.env` if demonstrating treatment generation.
- Configure Telegram bot token and chat id if demonstrating notifications.
- Ensure the Pi camera or a sample image is available in `captures/`.

Demo steps (short)
1. Start the backend and confirm `http://localhost:8000/docs` loads.
2. Start Phase 6 with a source image:

```powershell
python -m phase6.main --source-image captures/sample.jpg --skip-backend false --skip-telegram false
```

3. Observe the console: the workflow will capture/copy image, run TFLite inference, estimate severity, call OpenRouter (if configured), sync to backend, and attempt Telegram delivery.
4. Inspect backend `/detections` and `/recommendations` via the Swagger UI.
5. Inspect `phase6` SQLite session database to review stored session rows.

Expected outputs
- A detection JSON containing `crop`, `disease`, `confidence`, and `severity` fields.
- A treatment recommendation JSON persisted to the backend (if OpenRouter configured and allowed).
- A Telegram message with summary fields (if configured).

Validation checkpoints
- Confirm `phase4.app.inference` produces the documented JSON fields.
- Confirm severity images generated by `phase4.app.validate_severity` when run separately.
- Confirm backend stores detection and recommendation rows and that inventory check is performed when a matching inventory item exists.
